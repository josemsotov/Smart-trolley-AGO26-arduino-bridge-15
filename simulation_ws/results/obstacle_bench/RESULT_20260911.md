# Temporary motorized obstacle-stop bench

User confirmed suspended/free wheels and access to cut motor power.
bench_obstacle_stop.py dry default publishes only /bench_obstacle/dry_command.
Armed wrapper stops ONLY normal mux, retains sensors/bridge, checks exactly
one /cmd_vel publisher, finally restarts main stack. No permanent gate installed.
20s forward maximum, .125m/s request, 2s ramp. PI/heading/balance off;
smooth floor18 and opto scale100. Sensor thresholds raw distances, NOT robot
footprint clearances: frontal +/-30deg lidar and center-third Kinect ROI.
Preflight2s clear>=1.2m; stop<.8m or insufficient valid samples or missing
scan>.35s/depth>.5s/motor>.7s or RPM>120. Stop latch cannot clear in invocation.
Operator requests on /field/mode_request and /stadia/control latch stop;
emergency field also latches. This is bench-only, not general collision safety.

Six latch tests passed, and initial dry run kept motor telemetry zero.
Armed file obstacle_armed_20260911_231446.json: wheels commanded for20s,
front measurements remained ~1.31m. Stop reason time_limit; zero commands
persisted through end, motor telemetry PWM/RPM zero. No obstacle was observed
below threshold during drive, so physical obstacle-triggered stop NOT validated.
Do not infer actual braking time from RPM reset-to-zero telemetry.
